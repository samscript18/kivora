# Three-minute operator walkthrough

This walkthrough uses whatever the connected Wheelhouse account returns. Do not quote fixed properties or revenue figures.

1. **0:00–0:25 — Live proof.** Show integration capabilities and the latest scan timestamp. State that the connected Wheelhouse listing, KPIs, and recommendations are live API responses.
2. **0:25–0:55 — Revenue War Room.** Show the ranked priority queue, portfolio health, incidents, market signals, and revenue exposure.
3. **0:55–1:25 — Explainable audit.** Open a detected incident. Walk through root cause, Wheelhouse rate comparison, KPI evidence, impact estimate, and confidence.
4. **1:25–1:50 — Prove before changing.** Run the live Wheelhouse preview and point out `mutated: false`. If the key has write access and an actual change is appropriate, obtain explicit approval before applying it.
5. **1:50–2:15 — Demand intelligence.** Refresh Ticketmaster/OpenWeather signals, then compare conservative, balanced, and aggressive Wheelhouse previews.
6. **2:15–2:35 — Operations at scale.** Show portfolio KPIs, segments, opportunities, activity, and a grounded Groq report.
7. **2:35–3:00 — Mobile loop.** Show a separately linked Telegram user receiving a briefing, asking a portfolio question, and running a non-mutating preview.

If an upstream system is unavailable, show the real failure state. Kivora must never substitute synthetic data or claim that a write happened when it did not.
